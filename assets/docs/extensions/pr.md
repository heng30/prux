# pr（把这一版改动交付成一个 PR）

`pr` 扩展把「改完了」变成「推上去了」：`/pr run` 时建分支、提交、推送、开 PR，等 CI 与评审
出结论，然后把这个结论贴回聊天区。

- 扩展名：`pr`（`settings.json` 的 `enabledExtensions` / `/extension` 面板切换）
- **默认关闭**：只在 `Dev` 模式注册。它会写 git 历史并推远端，只能由你显式打开。
- **只有 `/pr run` 会交付**：没有任何自动触发点，也不在结算边界上动作。推什么、什么时候
  推，由你决定。
- 不提供任何模型可见的工具：对工具列表和系统提示没有影响。
- **永远不会 merge**：最高只到开 PR。

## 交付流程

`/pr run` 一次：

1. 确认工作目录在 git 仓库里；不是仓库就静默跳过。
2. 若当前在基线分支上，就新建一条 `prux/<日期>-<时分>` 分支再干活，不往基线上直接提交。
   「基线」的判定顺序：配置里的 `base` → `origin/HEAD` 指向的分支 → 约定俗成的名字
   （`main` / `master` / `trunk`，给没有远端的新仓库兜底）。
   已经在 `prux/...` 分支上时，改动提交到同一条分支——那个 PR 被更新，而不是再开一个
   （那条 PR 已经关了就另说，见第 5 步）。
3. `git add -A` + `git commit`，提交信息是 `prux: <本会话第一条需求的单行摘要>`。
4. `git push -u origin <分支>`。
5. 确认 `gh` 已登录 → 确定目标分支（`base`，留空则由 `gh` 探测仓库默认分支）→ 这条分支
   已有**开着**的 PR 就复用，否则 `gh pr create`（`draft` 控制是否草稿）。已关闭 / 已合并的
   PR 不复用：再往上推它也收不到新提交，所以另外开一个新的，并在聊天区说明旧的那条关着。
6. 轮询 PR 状态，直到全绿 / 有阻塞 / 超时，把结论贴回聊天区。

工作区干净且不在 `prux/` 分支上时不做事（报「nothing to deliver」）；干净但停在 `prux/`
分支上时，只重新查一次那个 PR 的 CI 状态。

## 配置

`agent_dir()/extensions/pr.json`（全局唯一，没有项目级配置——能提交进仓库的配置不该有权改
你的推送目标）：

```json
{
  "timeoutSecs": 900,
  "pollSecs": 20,
  "base": "",
  "draft": false
}
```

| 键 | 缺省 | 含义 |
|----|------|------|
| `timeoutSecs` | `900` | 一次 `/pr run` 等 CI 出结论的总时限；超时按「还在跑」收手 |
| `pollSecs` | `20` | 轮询间隔。推完先等满一个周期再读状态，否则可能读到上一次推送的结论 |
| `base` | `""` | PR 目标分支；留空用 `gh repo view` 的默认分支 |
| `draft` | `false` | 开 PR 时是否用 draft |

缺键会自动回填；文件写坏了不会被覆盖，配置退回缺省值。

## 命令

| 命令 | 作用 |
|------|------|
| `/pr`（或 `/pr status`） | 打印当前配置、本会话的分支 / PR 号、最近一次的结论 |
| `/pr run` | 现在交付一次：提交 → 推 → 开 PR → 等 CI 结论 |

`/pr run` 在后台线程执行（等 CI 可能是分钟级），结果回聊天区，不阻塞界面。同一时刻只允许
一次交付在跑，连点会被忽略。

## CI 红了怎么办

不自动续跑。`/pr run` 结束时会列出血的检查（`名称 — 结论`）与要求修改的评审
（`作者: 正文`）以及 PR 链接，你让 agent 照着修，再跑一次 `/pr run`：改动提交到同一条分支，
同一个 PR 被更新，再等一次结论。

等满 `timeoutSecs` 还没出结论时，只报「还有 N 个检查 pending」，不猜结果。

## 三条不越的线

- **不替你合并**：合入看的是人。
- **不自动交付**：没有结算边界钩子、没有把失败喂回模型的循环。代码有没有问题、值不值得
  开 PR，先由你看过再决定。
- **不猜远端**：`origin` 不存在、`gh` 没登录、探测不出默认分支，一律停下报原因，不做兜底推送。

## 和 vet 的分工

- `vet` 管**本机**：结算前跑测试 / lint / 类型检查，红了就喂回去继续修。
- `pr` 管**交付**：本地过了不等于 CI 会过，它负责把改动推上远端并把**远端**的结论带回来。
